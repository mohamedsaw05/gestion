## 2. Invariants Métier Validés dans le Code

1. **Isolation Stricte Multi-Entreprise** :
   Chaque requête SQL transite par `PrismaTenantService` qui applique `SET LOCAL app.current_tenant_id = :tenantId`. Les tests négatifs confirment qu'une injection d'ID étranger est bloquée au niveau moteur de la base.
2. **Pas de Stock Négatif Non Autorisé** :
   Le verrou pessimiste `SELECT ... FOR UPDATE` empêche deux ventes simultanées de dépasser la quantité disponible. En cas d'approvisionnement immédiat, une écriture d'ajustement positive est commitée de façon strictement liée dans la même transaction.
3. **Immutabilité des Écritures Comptables & Documents** :
   Les factures, reçus, mouvements de stock et mouvements de crédit sont enregistrés en mode *append-only*. Aucune mise à jour destructive n'est permise sur les écritures passées.
4. **Séparation Physique Client / Admin** :
   La console propriétaire (`apps/admin`) est un bundle frontend séparé avec sa propre configuration et son propre point d'entrée, garantissant qu'aucun code d'administration globale n'est exposé dans le bundle client.
5. **Pagination Universelle et Sélecteurs Compacts** :
   Toutes les listes sans exception sont plafonnées à 20 éléments par page par défaut. Le sélecteur de recherche de vente est borné à 10 résultats pour préserver une réactivité instantanée (< 50ms).
6. **Conformité Réglementaire et Respect des Politiques de Plateforme** :
   Les relances de crédit par WhatsApp sont strictement verrouillées par défaut conformément à la politique Meta Business interdisant le recouvrement de dettes par messagerie automatisée. Les fenêtres de 24h et les kill-switches sont appliqués de manière fail-closed.
